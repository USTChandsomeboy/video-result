## 改了什么

1. 颜色保留 RGB 和透明度，不再把通道混合排序。SVG 轮廓保留二维坐标，检查图形在组内的相对位置，允许路径反向绘制和简单拆分。
2. 静态属性和位置从单个锚点扩展到多个可见状态；完全透明或屏外部件不再参与这些外观检查。原始 DOM 元素数量不等于必需部件数量，因此不再作为外观扣分项。
3. 位置误差换算成像素：2 像素以内不扣分；零分阈值由原对象的尺寸确定，范围为 12–36 像素。动效中的位置/宽高误差使用 2–24 像素区间。
4. 绑定检查比较目标对象属性变化的方向和强度。它仍以公开对象为单位；组内无独立 ID 的成员不能声称逐个对应。
5. 运动检查比较同一时刻的值和幅度，使用 70% 均值加 30% 第 90 百分位误差，避免局部明显错误被长时间正确状态完全稀释。
6. 时序增加动作累计变化达到 10%、50%、90% 的时间点，并保留可见区间检查。容差为 2 帧，偏差达到 12 帧的该项为零分。

这些是此版明确的工程容差，已通过定向源码试验检查灵敏度；尚未声称经过大规模人工偏好校准。新分数表示这套源码规则下的还原程度，不是整体美学分。

## 校准结果

共享测试包含 17 份真实 TSX 变体、48 项断言。红色改蓝色、斜线翻转、动作反向或错绑能被检出；交换路径绘制方向、简单路径拆分和组件包装保持 100。副标题删除、4/12/30 像素错位、2/6/12 帧延迟、10%/25% 幅度偏差均有具体数值记录。

每条实际案例另运行原作自对照、带公开标记的等价原作、六维改错源码和已有复刻四组检查；校准记录、规则、原作指纹与测量器一起封存。Kinetic、LinkPulse、Showreel、TeamLaunch 最终评分重新读取复刻源码测量。SketchDay 因本机内存压力，交付时复用了原始源码观测：先核对当前全部可执行源码、样式和 SVG，以及 JS 测量器指纹完全相同，再用已封存 v3 规则重新计算。具体指纹记录在 scores.json 的 measurement_replay；没有复用旧分数。

共享测试报告：[v3-source-calibration/report.json](v3-source-calibration/report.json)。典型扣分证据见 [v3-selected-evidence.json](v3-selected-evidence.json)。案例规则在各目录 verifier-v3/；新结果在 evaluation-v3/；旧版 verifier-v2/ 和 evaluation-v2/ 保留。

## 范围

公开对象内部仍为有界绘制集合比较：颜色最多比较 24 个代表绘制节点，轮廓最多 24 个路径和 96 个代表采样点。未提供成员身份的角色/点阵不能声称逐个成员匹配。基于浏览器 getBBox 的路径测量不等同于完整渲染像素；任意旋转/倾斜后的局部路径坐标仍有近似，滤镜、复杂遮罩、图层遮挡的最终合成、精确字形和音频不在分数内。渐变仍按计算后的 CSS 定义比较，复杂等价渐变的感知一致性尚未验证。

Reel26、FullStop、Horizon 的源码评估仍未完成。它们现在另有视频对比总分，见 [视频对比分数说明](VIDEO-PROVISIONAL.md)：Reel26 58.5、FullStop 43.8、Horizon 71.9。该结果按交付视频比较，和以上 v3 源码分数使用不同方法。
