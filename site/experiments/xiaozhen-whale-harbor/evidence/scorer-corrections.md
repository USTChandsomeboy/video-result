# 本次评分器修正

早期的 50.73 分已撤回。复刻代码和视频保留原样，评分器修正后重新计算；正式结果为 **63.73 分**，见对比页与 `final/scores.json`。

| 问题 | 修正 | 核对方法 |
| --- | --- | --- |
| 歌词编号通过 `String(i + 1).padStart(2, '0')` 生成。解析器不支持这个写法，把可见歌词误判为缺失。 | 支持有界的字符串补齐；编号解析失败时保留失败原因。 | 检查动态对象编号、逐字编号、重复编号和未知编号；抽查原始提交中的实际歌词节点。 |
| 绝对定位的字幕套用了底部居中的计算方法，又加上父元素位置，得到超出画布的位置。 | 在字幕容器内计算字框，再统一应用父元素的位移和缩放。 | 已知坐标、父级缩放、等价包装与布局负例；实际字框纵坐标从错误的 1953 恢复为 946.1。 |
| MP4 容器长 34.048 秒，但其中画面恰好是 34 秒、1,020 帧；多出的时间来自音轨尾部补齐。 | 分别记录画面时长、帧数和容器时长。 | 实际 ffprobe 结果及错误帧数、错误帧率等反例。 |

本次修正保留同一份原作、复刻提交、3,534 项检查、权重和容差。解析、语义与视频规格的 189 项测试已通过；完整标准数据核对、对照测试及 Docker 运行记录保存在实验的 `protocol.json` 和对应试验目录中。
