# 第九轮：先配齐对应图像，再做复杂素材复刻

## 本轮有什么

这次找的是原作者公开提供原始图片或 PSD 图层的作品。不是拿一个人的视频配另一个人的照片。当前选中 3 条短片段，共 64 份对应图像，复刻只测试视觉。

| 参考片 | 长度 | 对应素材 | 想检验的动作 | 目前限制 |
|---|---:|---|---|---|
| [Nike 球鞋动效](https://www.youtube.com/watch?v=vnjUIE7YsEk) | 9 秒 | 原作者同一球鞋 PNG、纸张纹理 | 产品轮廓、拖影、背景动字 | 字体未配齐；内容是产品海报，不是完整广告叙事 |
| [香蕉人物拼贴](https://www.youtube.com/watch?v=QoYdlYNjT3k) | 6.24 秒 | 38 个图层：人头、木偶身体、鞋、香蕉、拳头、衣袖、胶带等 | 关节连接、香蕉跨场景运动、手与物体接触 | 短片段；字体和撕纸外形需重建；保留原作者角标 |
| [打字机与真实手部](https://www.youtube.com/watch?v=YcXdZBrA1mA) | 6.4 秒 | 23 个图层加纸张：机器、按键、滚筒、手柄、左右手各六种姿态 | 手部姿态切换、触键、手柄与滚筒配合 | 字体未配齐；这是编辑拼贴，没有完整软件操作流程 |

作品来源有 YouTube、作者 Patreon 附件、作者 Google Drive 素材包。也检索了 Ordinary Folk、SonduckFilm、Motion Nations 和 Motion Nerds，未配齐素材的候选不进入复刻。没有新用 Mixkit。

这 3 条是不同内容类型的素材合成小批次，不代表已经覆盖原来的五大类别。

## 怎样给 agent 输入

每个 agent 只收到自己的 `reference.mp4` 和 `assets/`，以及相同的复刻要求。不能读取作者的教程、动画工程、关键帧、其他试验结果或本轮 seed。主 agent 只从 PSD 中导出独立的静态透明图层，不提供原布局坐标；成片帧不能当作素材。

条件名称为“提供对应关键图像”，没有称为所有素材齐全，因为字体没有拿到。

每条保留首次成功渲染。可以修构建错误；首次成片后不根据主 agent 的观察修画面。主 agent 统一检查差异。

## 缺素材对照

同一条参考视频复制给新的、无历史上下文的 agent，分别拿掉：

- 球鞋：拿掉 `shoe.png`。
- 香蕉人物：拿掉 `21-head.png`。
- 打字机：拿掉全部 13 张真实手部姿态。

除此之外输入要求保持一致。两次都是独立复刻，不能从第一次代码替换一个占位图冒充第二次试验。当前每种条件只做一次，不足以统计模型稳定性。

## 如何核验

1. 输入先核验主体是不是同一件产品/同一个人物，背景是否对应，是否存在缺失素材。
2. 输出先用 ffprobe 检查宽高、帧率和解码帧数，再用 ffmpeg 完整解码；仅能证明文件可播放。
3. 主 agent 对照同一时间点，分别看外观、部件连接、动作时序和漏掉的内容。
4. 输入差异不能算模型弱点；代码错误不能证明参考视频本身很难。
5. seed 先记作下一轮搜索假设，跨类别复现之后才增强结论。

## 查看和重跑

在项目根目录启动 `npm run compare`，打开 `http://127.0.0.1:8770/compare-round09.html`。页面展示原片、首次复刻、实际素材缩略图和输入限制；未出片的条件有明确状态。

每个 `experiments/r09-*/` 都有 `selection.json`、`asset-manifest.json`、`reference.mp4` 和 `assets/`。首次代码与渲染命令由执行 agent 记录。不能把整份源 PSD 或作者动画工程送给复刻 agent。

工作脚本：

```sh
python3 work/round09_tasks/validate.py
python3 work/round09_tasks/review_frames.py
python3 work/round09_tasks/update_viewer.py
```

`technical-validation.json` 只检查编码与完整解码，不是美学分数。素材来源公开不代表已经获得打包再发布许可，当前先用于本地实验。

## 第八轮更正

第八轮所配素材不对应原片，现已标为输入不合格，撤回根据它得出的模型弱点结论。原代码、成片和旧报告保留。两条 missing-recreation 视频只是人工替换占位图演示，不能用于评估。

## 本轮结果（已完成）

三条视频分别做了两次独立复刻，共 6 个首次输出，全部通过帧数、尺寸、帧率和完整解码检查。原始输入图片的哈希未改变；两种条件下的参考片逐字节相同。agent 自行生成的裁切图和拖影图不计入“提供素材”数量。

| 视频 | 提供对应图像后 | 拿掉关键图像后 | 目前判断 |
|---|---|---|---|
| 球鞋 | 整体构图、产品、拖影较接近，背景与侧边字有差异 | 用 SVG 画鞋，照片质感和细节损失 | 保留作较容易的对照，暂不当作高难失败样本 |
| 香蕉人物 | 1.56 秒香蕉位置不准；3.12 秒拳头偏小；4.68 秒香蕉状态切换不准 | 人头变为插画，腿部姿态与拳头尺寸仍有差异 | 值得继续找“同一物体跨镜头运动”“多部件配合”的视频 |
| 打字机 | 3.20 秒原片仍在打字，复刻左手已移向手柄 | 手变成简化灰色图形，触碰手柄的姿态也不准 | 值得继续找“手与产品接触”“多个姿态按正确时间切换”的视频 |

这些是主 agent 对相同时间点的观察，不是自动分数，也不能据一次运行推断模型普遍能力。两条件都禁止外部检索；缺素材结果反映“仅用剩余素材和代码”这一限制下的表现。没有测开放图像生成工具条件。

## 下一轮怎样沿着难点找

| 简单 seed | 本轮依据 | 换类别时找什么 | 入选前必须拿到什么 |
|---|---|---|---|
| 多个部件一起动，位置不能散 | 香蕉人物姿态、拳头与香蕉相对位置偏差 | 知识讲解中的关节/机器运动；产品组装广告 | 各部件独立图像；参考不能依赖无法获得的实拍动作 |
| 手要在正确时间碰到正确位置 | 打字机 3.20 秒左右手动作不同步 | 产品按键演示；软件演示中真实手指点击手机 | 原手姿态或原手部视频、产品/UI 素材；点击前后状态清楚 |
| 换图的时间要对 | 香蕉 4.68 秒状态错误；打字机手姿态错时 | 产品颜色/款式切换；知识讲解中的物体状态变化 | 所有状态的原图，不能只给其中一张 |
| 放大或切镜头后仍跟得上同一物体 | 香蕉 3.12 秒拳头、香蕉、云的比例和位置偏差 | 产品特写切换；品牌拼贴中人物/物体穿越画面 | 同一物体的对应图像；能用裁切、缩放、遮罩完成 |

以上都是搜索假设。香蕉与打字机均出现时序问题，但还没有完成原五类之间的验证，不能写成“已证明跨类别 weakness”。每条新候选只需命中其中一个 seed，不要求同时满足全部。优先补产品营销、知识讲解和真实手操作软件的样本；数据叙事仍需独立筛选，不硬套人物素材。
